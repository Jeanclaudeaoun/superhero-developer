# Accounts API

Everything the API knows about an `ak_...` address: its profile fields and links, the tokens it
holds, its portfolio value over time, its realized and unrealized PnL, and where it sits on the
trading leaderboard. This is the richest part of the API and the part agents lean on hardest.

All paths are relative to `https://api.superhero.com`. Reads need no authentication.

## Endpoints

| Method & path | Query | Returns |
| --- | --- | --- |
| `GET /api/accounts` | `search`, `order_by`, `order_direction`, `has_nostr`, `limit`, `page` | Paginated account rows |
| `GET /api/accounts/{address}` | — | One account aggregate |
| `GET /api/accounts/search` | `q`, `limit` | Typeahead matches |
| `GET /api/accounts/chain-names` | `addresses` | Batch address to `.chain` name map |
| `GET /api/accounts/by-nostr` | `pubkeys` | Nostr pubkey to account map |
| `GET /api/accounts/{address}/tokens` | `order_by`, `order_direction`, `limit`, `page`, `search`, `owner_address`, `creator_address`, `factory_address` | Paginated holdings |
| `GET /api/accounts/{address}/portfolio/history` | `startDate`, `endDate`, `interval`, `convertTo`, `include` | Array of value snapshots |
| `GET /api/accounts/{address}/portfolio/tokens/history` | same | Snapshots with per-token PnL |
| `GET /api/accounts/{address}/portfolio/value` | `convertTo` | Latest value only |
| `GET /api/accounts/{address}/portfolio/stats` | `startDate`, `endDate` | Trading statistics |
| `GET /api/accounts/{address}/portfolio/pnl-chart.svg` | `startDate`, `endDate`, `convertTo`, `background`, `height`, `width` | An SVG sparkline |
| `GET /api/accounts/{address}/pnl` | `blockHeight` | PnL at a block height |
| `GET /api/accounts/leaderboard` | `window`, `sortBy`, `sortDir`, `page`, `limit`, `minAumUsd`, `startDate`, `endDate`, `tradingOnly` | Ranked traders |

Note the casing split: the account-scoped portfolio endpoints and the leaderboard use
**camelCase** `startDate` / `endDate`, unlike the snake_case `start_date` / `end_date` used
everywhere under `/api/analytics`. See [Conventions](/api/conventions).

## `GET /api/accounts/{address}`

Returns the account aggregate the web app types as `AccountAggregate`:

| Field | Type | Meaning |
| --- | --- | --- |
| `address` | string | The `ak_...` |
| `bio` | string or null | Legacy bio field |
| `chain_name` | string or null | Legacy `.chain` name field |
| `chain_name_updated_at` | string or null | ISO 8601 |
| `links` | object or null | Verified address links, see below |
| `profile` | object or null | Profile payload, see [Profile](/api/profile) |
| `public_name` | string or null | Resolved display name |
| `x_username` | string or null | Legacy X handle field |

`links` is where the current, verified identity lives:

| Key | Meaning |
| --- | --- |
| `x` | Verified X handle |
| `bio` | Verified bio text |
| `prefaens` (also `prefered_aens_name`) | Preferred `.chain` name |
| `site` | Verified website |

The `links`, `profile` and top-level fields are three generations of the same data. The web app
reads them with an explicit precedence — `links` first, then `profile`, then the legacy
top-level field:

```ts
// getLinkedXUsername, src/api/backend.ts
account?.links?.x ?? account?.profile?.x_username ?? account?.x_username
```

Do the same, and strip a leading `@` from the X handle as the app does.

```bash
curl -s "https://api.superhero.com/api/accounts/ak_2ruXgsLy9jMwEqsgyQgEsxw8chYDfv2QyBfCsR6qtpQYkektWB"
```

## `GET /api/accounts`

| Parameter | Notes |
| --- | --- |
| `search` | Matches address or name |
| `order_by` | `total_volume`, `total_tx_count`, `total_buy_tx_count`, `total_sell_tx_count`, `total_created_tokens`, `total_invitation_count`, `total_claimed_invitation_count`, `total_revoked_invitation_count`, `created_at` |
| `order_direction` | `ASC` or `DESC` |
| `has_nostr` | When true, only accounts with a linked Nostr key |
| `limit`, `page` | Standard pagination |

The `order_by` enum doubles as a list of the counters the API keeps per account — volume, trade
counts split by side, tokens created, and invitations issued, claimed and revoked.

```bash
curl -s "https://api.superhero.com/api/accounts?order_by=total_volume&order_direction=DESC&limit=10"
```

## Name resolution helpers

Two endpoints exist specifically so a feed does not have to make one request per row:

- **`GET /api/accounts/chain-names?addresses=ak_a,ak_b`** returns a map of address to `.chain`
  name or `null`. Every valid address you send is present in the result; invalid ones are
  silently dropped and **at most 25 are resolved** per call.
- **`GET /api/accounts/search?q=alice&limit=8`** is typeahead. `limit` is clamped to 1–20, default
  8, `q` is capped at 100 characters, and a `q` shorter than the minimum returns `[]` rather than
  an error. Items are `AccountSearchResultDto`: `address` and `chain_name`.

`GET /api/accounts/by-nostr?pubkeys=...` takes comma-separated npub or 64-character hex keys, at
most 200, and returns the matching accounts.

## `GET /api/accounts/{address}/tokens`

An account's holdings. `order_by` accepts only `balance`; `order_direction` is `ASC` or `DESC`.
The `search` parameter narrows server-side, which matters because **`limit` is capped at 100** —
an unfiltered fetch only ever returns the top 100 holdings by balance.

Item shape varies slightly by deployment, which the web app handles explicitly: usually
`{ token, balance, ... }` with the full `TokenDto` nested under `token`, but some environments
flatten it to `token_name` / `token_symbol` / `token_address` on the item itself. Read `item.token`
first and fall back to the item.

The agent skill reads `h.balance`, `h.aex9_address`, and `h.token.name` / `h.token.symbol` /
`h.token.sale_address` / `h.token.price` / `h.token.sell_price` / `h.token.trending_score`.

```bash
curl -s "https://api.superhero.com/api/accounts/ak_YOUR_ADDRESS/tokens?includes=token&order_by=balance&order_direction=DESC&limit=50"
```

Balances are in token base units — divide by 10 raised to the token's `decimals`.

## Portfolio history

`GET /api/accounts/{address}/portfolio/history` returns a **bare JSON array** of snapshots, not a
paginated envelope.

| Parameter | Default | Notes |
| --- | --- | --- |
| `startDate` | — | ISO 8601 |
| `endDate` | — | ISO 8601 |
| `interval` | `86400` | Snapshot spacing **in seconds**; 86400 is daily |
| `convertTo` | `ae` | One of the nine currency codes |
| `include` | — | Comma-separated. `pnl` adds aggregate `total_pnl`; `pnl-range` uses daily-window PnL instead of cumulative |

Each snapshot is a `PortfolioHistorySnapshotDto`:

| Field | Type | Meaning |
| --- | --- | --- |
| `timestamp` | string | ISO 8601 |
| `block_height` | number | Height at the snapshot |
| `ae_balance` | number | Bare AE held, in **AE** |
| `usd_balance` | number | USD value of the AE balance |
| `tokens_value_ae` | number | Value of all token holdings, in AE |
| `tokens_value_usd` | number | The same in USD |
| `total_value_ae` | number | `ae_balance` plus `tokens_value_ae` |
| `total_value_usd` | number | The same in USD |
| `ae_price` | number | AE/USD rate at the snapshot |
| `version` | number | Snapshot format version |
| `total_pnl` | `TotalPnlDto` | Only when `include` requests it |
| `tokens_pnl` | object | Per-token breakdown keyed by `sale_address`. **Only** from `/portfolio/tokens/history` |

Unlike the token fields, these are plain numbers already in AE and USD — no 1e18 division.

`TotalPnlDto`:

| Field | Type | Meaning |
| --- | --- | --- |
| `percentage` | number | Total PnL as a percentage |
| `invested` | `PnlAmountDto` | Total invested |
| `current_value` | `PnlAmountDto` | Current total value |
| `gain` | `PnlAmountDto` | Total gain or loss |

`PnlAmountDto` is simply `{ ae, usd }`, both numbers.

```bash
curl -s "https://api.superhero.com/api/accounts/ak_YOUR_ADDRESS/portfolio/history?interval=86400&convertTo=ae&include=pnl"
```

This is the slowest endpoint in the API — the web app allows it 90 seconds before aborting. Bound
it with `startDate` and `endDate` rather than asking for all history at a fine `interval`.

For a live ticker use **`GET /api/accounts/{address}/portfolio/value`** instead, which returns
just `{ value, timestamp }` and takes `convertTo` of `ae` or `usd`.

## `GET /api/accounts/{address}/portfolio/stats`

`TradingStatsResponseDto` — realized trading quality over a date range. `startDate` defaults to
30 days ago (inclusive), `endDate` to now (exclusive).

| Field | Type | Meaning |
| --- | --- | --- |
| `top_win` | `PnlAmountDto` | Largest single realized gain from any sell in the range |
| `unrealized_profit` | `PnlAmountDto` | Current unrealized profit across all tokens still held — **all-time holdings, not date-filtered** |
| `win_rate` | number | Percentage of sells in the range that produced a positive gain |
| `avg_duration_seconds` | number | Average hold time from first buy to sell |
| `total_trades` | number | Sell transactions in the range |
| `winning_trades` | number | Sells with a positive gain |

`GET /api/accounts/{address}/pnl?blockHeight=N` gives point-in-time PnL instead:
`block_height`, `total_pnl` and a `tokens_pnl` map keyed by sale address. `blockHeight` defaults
to the current height.

## `GET /api/accounts/leaderboard`

Ranked traders. Two modes:

- **Precomputed window.** Pass `window` of `7d`, `30d` or `all`. Metrics are precomputed per
  window.
- **Custom period.** Pass `startDate` **and** `endDate` together. Leaders are then ranked by
  selected-period performance among accounts that traded in that range, and both the top-level
  metrics and the buy/sell counts are scoped to it. Pass `tradingOnly=true` to base period PnL and
  ROI on realized token-trading PnL only, excluding transfer-driven portfolio changes.

| Parameter | Notes |
| --- | --- |
| `sortBy` | `pnl`, `roi`, `mdd` or `aum` |
| `sortDir` | Defaults to `DESC`, except `sortBy=mdd` which defaults to `ASC` |
| `minAumUsd` | Exclude leaders below this USD AUM |
| `page`, `limit` | The web app uses `limit=18` |
| `points`, `maxCandidates` | Both deprecated and currently ignored |

Items carry `address`, `chain_name`, `aum_usd`, `pnl_usd`, `roi_pct`, `mdd_pct`, `buy_count`,
`sell_count`, `volume_usd`, `created_tokens_count`, `owned_trends_count` and
`portfolio_value_usd_sparkline` (an array of `[timestamp, value]` pairs).

The `meta` here is **not** the standard envelope: it carries `page` (not `currentPage`), `limit`,
`totalItems`, `totalPages`, `window`, `sortBy`, `sortDir` and a `timeFilter` of
`{ value, unit, start, end }`.

**Responses are cached for up to 60 seconds**, and `meta.timeFilter.start` / `end` reflect when
the cache entry was filled rather than the moment of your request.

```bash
curl -s "https://api.superhero.com/api/accounts/leaderboard?window=30d&sortBy=roi&sortDir=DESC&limit=18&page=1"
```

## Open questions

- **What exactly is in a `/api/accounts` list row?** The endpoint is typed `any` in the generated
  client and the web app renders only `items`, `meta.currentPage` and `meta.totalPages` plus the
  counters named in the `order_by` enum. The full row shape is unverified.
- **Is `mdd_pct` drawdown as a positive or negative percentage?** `sortDir` defaults to `ASC` for
  `mdd`, which implies smaller is better and therefore a positive magnitude — but the sign is not
  stated anywhere.
- **How far back does portfolio history go, and at what granularity is it stored?** `interval` is
  a request parameter, not a description of the underlying snapshot cadence. Whether a 3600-second
  interval interpolates or returns real hourly snapshots is not discoverable from the client.
