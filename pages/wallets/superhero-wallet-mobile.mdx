# Superhero Wallet — Mobile

On a phone there are three ways to hold an account for Superhero, and they are easy to confuse
because two of them are called "Superhero". This page separates them, then covers the install paths
and what changes once the app is installed rather than opened in a tab.

## Two different apps

| App | Stores | What it is |
| --- | --- | --- |
| **Superhero — Web3 Communities** | [App Store](https://apps.apple.com/us/app/superhero-web3-communities/id6758045846) · [Google Play](https://play.google.com/store/apps/details?id=com.superhero.apps) | The Superhero social app, **with a wallet built in** |
| **Superhero Wallet** | [App Store](https://apps.apple.com/us/app/superhero-wallet/id1502786641) · [Google Play](https://play.google.com/store/apps/details?id=com.superhero.cordova) | The standalone multi-chain wallet, which signs for other æpps too |

If you want to use Superhero, install the first. If you already have an æternity account elsewhere,
or you want one wallet across several chains, install the second and connect it.

The Superhero app's own description: a built-in wallet so you can post, trade, tip and govern
without leaving the app — no extensions, no friction.

## Install Superhero as a PWA — no app store

Superhero is also installable straight from the browser. The installed app gets a home-screen icon,
a full-screen experience, an integrated wallet and push notifications.

### iOS

**Safari only.** Chrome and Firefox on iOS cannot install a PWA — the app says so explicitly in its
install guide.

1. Open [superhero.com](https://superhero.com) in Safari.
2. Open the page menu — the app's install guide points at the **⋯** menu in the top-right; on older
   iOS versions this is the **Share** button. Whichever your Safari shows, it is the menu containing
   sharing actions.
3. Scroll and tap **Add to Home Screen**.
4. Tap **Add** in the top right. The icon appears on your home screen.
5. **Launch it from the home-screen icon**, not from Safari — the extra capabilities only exist in
   standalone mode.

### Android

1. Open [superhero.com](https://superhero.com) in Chrome.
2. Tap the **⋮** menu in the top right.
3. Tap **Add to Home screen** or **Install app**.
4. Confirm with **Install**.
5. Launch from the home screen.

On desktop, the same install is available from the install button in your browser's address bar.

## What changes once it is installed

Running as an installed app is not cosmetic. Several behaviours are gated on it:

| Behaviour | Browser tab | Installed app |
| --- | --- | --- |
| Create a built-in wallet (passkey or new phrase) | Yes | Yes |
| **Import** an existing seed phrase or private key | No — Connect instead | **Yes** |
| In-page signing by the built-in wallet | Not installed as the signer | **Yes** |
| Token community chat entry points | Hidden | **Shown** |
| Location sharing on iOS | Not available | Available |
| Push notifications | No | Yes |

The import restriction is deliberate rather than an oversight. In a browser tab the answer to "I
already have a wallet" is Connect, which hands signing to the extension or the wallet app and never
asks for your secret. That handoff is a redirect, and a redirect out of an installed app does not
come back cleanly — which is exactly why the installed app needs a way to take the key directly and
the web does not.

## The built-in wallet on mobile

Tapping **Connect** in the installed app offers a passkey option first. On a phone that means Face
ID, Touch ID, a fingerprint or your device PIN, and it creates a real æternity account in one
ceremony — no seed-phrase screen, because the seed is *derived* from the passkey rather than stored
beside it.

The caveat to internalise before you fund it: **that only works as a backup if the passkey syncs**
(iCloud Keychain, Google Password Manager). There is no phrase reveal or export screen in the app
today. Enroll the recovery code the flow offers you, and read
[The Built-In Wallet](/wallets/built-in-wallet) for what each factor does and does not survive.

## Push notifications

Push is standard Web Push (VAPID), not a native notification channel, and it is opt-in behind a user
gesture. `enablePush()` in `src/features/notifications/notification-feed-client.ts` runs this
sequence, returning a state at each point it can stop:

| Step | Returns if it stops here |
| --- | --- |
| Check the browser supports push at all | `unsupported` |
| Fetch the server's VAPID public key | `unconfigured` — the backend has no key set |
| `Notification.requestPermission()` — **this is the OS prompt** | `denied`, or `default` if dismissed |
| Register `/notifications-sw.js` as a service worker, scope `/` | — |
| `pushManager.subscribe({ userVisibleOnly: true, applicationServerKey })` | — |
| Register the endpoint with the backend under your bearer token | — |

Three things follow that are worth knowing before you go looking for a setting:

- **Exactly one permission is requested** — the browser's notification permission. No location, no
  contacts, no background-refresh grant. `userVisibleOnly: true` means the browser will not deliver
  a push that does not show a notification, which is what stops silent background wake-ups.
- **It can be unavailable through no fault of yours.** If the server has no VAPID key configured,
  the app reports "Browser push is not configured on the server (no VAPID key)" and stops before
  prompting you. The backend side is `superhero-api/src/notifications/`, and its public-key route
  deliberately returns nothing when the key pair is incomplete, so the app does not prompt for a
  channel that cannot deliver.
- **It must be triggered by a tap.** The permission prompt requires a user gesture, so push is
  enabled from a control in the app, never automatically on load.

If a server VAPID key is rotated, an existing subscription made with the old key can never receive a
push; the client detects the mismatch, unsubscribes and re-subscribes rather than leaving you
silently unnotified.

## The standalone Superhero Wallet apps, and how they differ from a PWA

The iOS and Android apps are the **`PLATFORM=ionic` build** of
`superhero-com/superhero-wallet` — Ionic Vue wrapped by Capacitor (`capacitor.config.ts`, app id
`com.superhero.cordova`, app name "Superhero Wallet"). They are the same `src/` tree as the browser
extension and the hosted web wallet, built with `npm run build:android` or `npm run build:ios`.

That matters for a question people ask a lot: **is installing `wallet.superhero.com` to your home
screen the same as installing the app?** No. An installed PWA is still the web build
(`PLATFORM === 'web'`), and the code branches on `IS_MOBILE_APP`, which is `PLATFORM === 'ionic'`.
The differences are concrete:

| | Installed PWA of the web wallet | Native app |
| --- | --- | --- |
| Platform flag | `IS_WEB` | `IS_MOBILE_APP` |
| Where the seed lives | Site `localStorage`, encrypted under your password | OS keychain via Capacitor Secure Storage, `whenUnlocked` access, encrypted with a per-install key |
| Unlock | Password (or none, if you turned protection off) | Biometrics — Face ID, Touch ID, fingerprint — or the device credential |
| Default auto-lock | 5 minutes of inactivity | **Immediately** |
| In-app dæpp browser | No | **Yes** |
| QR scanning | Browser camera via a JavaScript scanner | Native scanner (ML Kit) |
| Ledger over WebUSB | Yes, on Chromium | **No** — the button is hidden on mobile |
| AirGap pairing | Yes | Yes |
| Deep links | `https://wallet.superhero.com/...` only | Also the `superhero://` scheme, and universal links on `applinks:wallet.superhero.com` |
| Survives "clear site data" | No | Yes |

Sources for each of those: the platform flags are in `src/constants/environment.ts`; the storage
split is `src/composables/storageRef.ts` choosing `SecureMobileStorage` over `WalletStorage` when
`enableSecureStorage && IS_MOBILE_APP`; the auto-lock defaults are `AUTHENTICATION_TIMEOUT_DEFAULT`
in `src/composables/auth.ts` picking `AUTHENTICATION_TIMEOUTS[0]` (0 ms) on mobile and
`AUTHENTICATION_TIMEOUTS[2]` (300000 ms) elsewhere; the dæpp browser is rendered under
`IS_MOBILE_APP || UNFINISHED_FEATURES` in `src/popup/pages/Dashboard.vue`, and
`UNFINISHED_FEATURES=false` in `.env.production`, so on a release build it is mobile-only; the
universal-link domain is in the repository README's iOS build steps.

The practical reading: **the native app is the stronger place to hold value on a phone** — keychain
storage and biometrics — and the PWA is the convenient one. Neither changes your backup obligation,
which is the seed phrase in both cases.

## Connecting the standalone Superhero Wallet app instead

On a mobile browser the app cannot detect an extension — there are none — so it uses a deep link.
Pressing Connect tries the `superhero://` scheme first; if the native app does not take over within
about 1.5 seconds, it falls back to opening `wallet.superhero.com`. The wallet signs and returns to
the app through the transaction queue route, described in
[Connecting a Wallet](/wallets/connecting).

## Open questions

- **Which iOS Safari control is current for Add to Home Screen?** The app ships two contradictory
  versions of this copy — the landing-page prompt says "Tap the Share button", the install guide says
  "Tap the three-dot menu (⋯)" — and both live in `src/locales/en.json`, so the repository cannot
  adjudicate between them. This needs one test on a current iOS Safari, after which the losing string
  should be fixed in the app rather than worked around here.
- **Does the "Superhero — Web3 Communities" store app differ from the installed superhero.com PWA?**
  This half of the question is still open, and now for a specific reason: `/home/user/superhero`, the
  web app's repository, contains **no native project at all** — no `capacitor.config.*`, no
  `android/` or `ios/` directory, no Cordova or React Native configuration. Its surface-gated
  behaviours key on *installed versus browser tab*, not on native versus PWA. So whatever the store
  builds wrap, they are produced from a source that is not in any available repository, and only
  Superhero can say what it contains. (The *standalone* half of this question is settled above: the
  Superhero Wallet native apps and the installed web wallet genuinely differ, and the table says
  how.) A screenshot-based walkthrough of native onboarding is still wanted for this page.
