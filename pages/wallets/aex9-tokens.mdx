# Managing AEX-9 Tokens

Every Superhero community token is an AEX-9 fungible token — the æternity equivalent of ERC-20.

## The AEX-9 surface

| Entrypoint | Arguments | What it does |
| --- | --- | --- |
| `meta_info` | — | Name, symbol, decimals |
| `total_supply` | — | Total minted supply |
| `balance` | `address` | One account's balance, as an option |
| `balances` | — | The whole balance map |
| `transfer` | `address, int` | Move your own tokens |
| `allowance` | `from_account, for_account` | Read a granted allowance |
| `allowance_for_caller` | `address` | Read the allowance granted to the caller |
| `create_allowance` | `address, int` | Grant a new allowance |
| `change_allowance` | `address, int` | Adjust an existing one by a delta |
| `reset_allowance` | `address` | Revoke it entirely |
| `transfer_allowance` | `from, to, int` | Spend someone else's allowance |
| `mint` / `burn` | `address, int` / `int` | Supply changes, owner-gated |

Amounts everywhere are integers in the token's **base units**. Divide by 10 to the power of
`decimals` from `meta_info` to get a human figure. Superhero's signing prompt does *not* do that
scaling — decimals are a per-token on-chain fact the decoder does not look up. Count the digits.

## Sale address vs token address

A community token has **two** contract addresses and they are not interchangeable.

| | What it is | What you use it for |
| --- | --- | --- |
| **Sale address** (`sale_address`) | The bonding-curve sale contract that mints and burns tokens against AE | Buying and selling on the curve; the DAO for that community; the token's page URL |
| **Token address** (`address`) | The AEX-9 contract that holds balances and allowances | Balances, transfers, allowances, adding the token to a DEX pool |

The backend's token object carries both fields — plus `bonding_curve_address` and
`factory_address` — so when you work from the API you never have to guess which one you have. When
something asks for "the token contract", it means `address`; when a DAO or a trade asks for a sale,
it means `sale_address`.

## How your balances are discovered

Superhero does not keep its own list of tokens you own. It asks the æternity **middleware**:

```text
GET {MIDDLEWARE_URL}/v3/accounts/<your ak_ address>/aex9/balances
```

The response is a `data` array plus a `next` cursor, which the app follows up to a cap of 20
pages. Each entry gives `contract_id`, an `amount`, `decimals`, and a token symbol and name.
Zero balances are dropped.

If the middleware returns nothing, the app falls back to probing: it takes the DEX's listed tokens
plus every token appearing in a pool, calls `balance(you)` on each contract directly, and fills in
symbol, name and decimals from `meta_info` where the listing did not supply them. The fallback is
slower and only covers tokens the DEX knows about.

A token you hold that the middleware has not indexed and the DEX has never listed may not appear
automatically.

## Add a token the app does not show

The screen at **`/defi/pool/add-tokens`** (the legacy path `/pool/add-tokens` still works) scans
your account for AEX-9 balances using the two mechanisms above, filters by name or symbol, and
tells you whether a DEX pool already exists for each token — the question to answer before you
add liquidity.

You need a **connected wallet** for it to have an account to scan. The address it works with is
the AEX-9 **token address**, not the sale address.

superhero.com has no manual-entry field: the screen discovers balances and does not accept an
arbitrary contract address.

### Superhero Wallet takes a pasted contract address

To see a token superhero.com will not show you, open Superhero Wallet — extension, mobile app or
`wallet.superhero.com` — and paste the token's `ct_...` **token address** (not the sale address)
into the asset selector's search box. When the term is a valid contract address and the selected
protocol is æternity, the selector switches to exact-contract mode, fetches the token's metadata
from the middleware (`GET /v3/aex9/<contract_id>`) and adds it to the available list — no pool, no
indexed balance and no DEX listing required. Anything else falls back to a name-prefix search.

## Allowances

An allowance grants a specific contract permission to move up to a stated number of *your*
tokens. Superhero relies on this in two places.

### DEX swaps

Swapping a non-AE token requires an allowance for the DEX router first. AE itself never needs one
— it is the native coin, not a contract balance.

The app manages this for you: it reads the current allowance, calls `create_allowance` if there is
none, and `change_allowance` with the *difference* if there is one but it is too small. It never
grants an unlimited approval.

The grantee is the router's **contract address re-encoded as an account address** — the same bytes
with the `ct_` prefix swapped for `ak_`. An allowance that looks like it was granted to an account
is in fact granted to the router contract.

### DAO vote locking

Governance votes lock the tokens you vote with until the vote closes, and that locking is
implemented with the AEX-9 allowance mechanism — which is what prevents the same tokens being
double-spent across two concurrent votes. Revoking your vote releases the lock.

This is why a vote can ask you to sign twice: once to grant or adjust the allowance, once to cast.

### Revoking an allowance

superhero.com grants allowances just-in-time before a swap or an add-liquidity and does not
provide a screen to review or revoke them. Revoke per token with a direct contract call:

```text
reset_allowance(for_account)   on the AEX-9 token contract
```

where `for_account` is the grantee in `ak_` form — for the DEX, the router's contract address with
`ct_` swapped for `ak_`. Use the agent skill's SDK setup, `aepp-cli`, or any tool that can call a
contract entrypoint.

Every allowance Superhero grants is sized to the specific trade, so a stale allowance is capped at
whatever was left over from the operation that created it — usually zero, because a swap spends
exactly what it was granted. Check, and revoke anything left standing on a token you hold in size.

### Hygiene

- **Read the amount** in the signing prompt.
- **Reset what you no longer need**, after you finish voting or when you stop using a pool.
- **Remember base units.** Check the digit count against the token's decimals.
