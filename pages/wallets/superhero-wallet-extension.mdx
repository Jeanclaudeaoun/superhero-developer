# Superhero Wallet — Browser Extension

On a desktop browser the extension is the standard way to use Superhero: it holds your key, it
signs, and superhero.com only ever receives the signed result.

## Install

| Browser | Listing |
| --- | --- |
| Chrome, Brave, Opera and other Chromium browsers | [Chrome Web Store](https://chromewebstore.google.com/detail/superhero-wallet/mnhmmkepfddpifjkamaligfeemcbhdne) |
| Firefox | [Firefox Add-ons](https://addons.mozilla.org/en-US/firefox/addon/superhero-wallet/) |

The Chrome extension ID is `mnhmmkepfddpifjkamaligfeemcbhdne`. superhero.com's connect dialog links
these two listings and shows you the one matching your browser. **Brave and Opera install the
Chrome Web Store build** — there is no separate listing for them.

There is no Safari extension. On Apple platforms the wallet ships as the native iOS app instead —
see [Mobile App](/wallets/superhero-wallet-mobile).

After installing, pin the extension so its icon is visible; the detection step below needs an
unlocked wallet. On Chromium you can also dock it in the **side panel**, and on Firefox in the
**sidebar**.

### Check which version you have

Open **More → About** in the extension. It shows the software version and commit hash, the SDK
version, and the node and middleware versions of the network you are on. The Chrome and Firefox
listings are reviewed separately and can sit at different versions for a while; this screen tells
you what you actually have.

## First run

The extension is a multi-chain wallet — æternity plus Bitcoin, Ethereum and others — so its
onboarding is not Superhero-specific.

**Create a new wallet.** Choose to create a wallet and follow the prompts. The seed phrase is not
shown during onboarding; go to **Settings → Seed phrase** and write it down — by hand, offline, in
two places — before funding anything. That phrase is the only thing that restores this wallet on
another machine. See [Backup & Recovery](/wallets/backup-and-recovery).

**Import an existing wallet.** Choose to import, and enter the seed phrase of an account you
already hold. Superhero's built-in wallet, the mobile app and this extension all derive accounts
from the same path, so the same phrase gives you the same addresses in all of them.

Either way, set a wallet password. It unlocks the extension on this machine; it is not a backup
and does not restore anything elsewhere. **The password can be changed later** — Settings → Secure
Login has a change-password form, an auto-lock interval (immediately, 1, 5, 15 or 30 minutes of
inactivity) and a switch to turn password protection off. Changing it re-encrypts the stored seed;
the account and its addresses are untouched.

**Hardware accounts.** Add account → **Add Ledger accounts** imports æternity accounts from a
Ledger over WebUSB, either by discovering accounts with existing activity or by deriving one at an
index you type. This button is hidden on Firefox, which does not implement WebUSB — use a Chromium
browser or the hosted web wallet. **Import AirGap accounts** has no such restriction. Both are
covered in [Choosing a Wallet](/wallets/choosing-a-wallet).

## Connect it to superhero.com

1. Unlock the extension.
2. Open [superhero.com](https://superhero.com) and press **Connect**.
3. Choose **Superhero Wallet** in the dialog, then **Connect**.
4. Approve the connection in the extension.
5. Your `ak_...` address appears in the app header.

Underneath, the app opens a browser message connection and runs the SDK's wallet detector for **4
seconds**. If the extension announces itself in that window, an RPC session opens and the app
subscribes to your address. If nothing answers and the page is not framed inside a wallet, the app
opens `wallet.superhero.com` instead — so *"it opened a web page instead of my extension"* means
the detector timed out.

After a page reload, the app tries to re-establish the session silently, with a longer
**15-second** window, because the extension's content script can be injected after the app has
already booted.

## What the connection grants

The extension keeps the key. Connecting lets the app read your address, your account list and
your balances, and lets it **request** signatures — each of which you approve individually in the
extension. There is no blanket spending approval and no session token. Full detail in
[Connecting a Wallet](/wallets/connecting).

## Switching accounts

With a live connection, account changes made in the extension are pushed to the app and the active
account follows your selection. Without one — a restored read-only session after a refresh — the
app does not notice the switch. Press Connect again to get the live session back.

## Networks

superhero.com is pinned to a single network at build time. The public site is mainnet, so keep the
extension on mainnet. There is no in-app switcher; you change the network in the extension under
Settings → Network. See [Using Testnet](/getting-started/testnet) for the testnet build.

## Common problems

| Symptom | Cause | Fix |
| --- | --- | --- |
| Extension not detected | Locked, disabled for this site, or slower than the 4-second window | Unlock, check site permissions, reload, press Connect again |
| The web wallet opened instead | Detection timed out and the deep-link fallback fired | Same as above; or use the web wallet as-is |
| Address shows but signing does nothing | Read-only static account, no RPC session | Press Connect to re-establish the session |
| App says disconnected while the extension is open | The five-second health check found no accounts on the SDK | Reconnect |
| Wrong network | The build is pinned; the wallet is not, and an æpp cannot make it switch | Switch networks in the extension, under Settings → Network |
| No "Add Ledger accounts" button | You are on Firefox, or the selected account is not æternity | Use a Chromium browser or the hosted web wallet, and select an æternity account |

More symptoms, including those specific to the built-in wallet, are in
[Troubleshooting](/wallets/troubleshooting).
