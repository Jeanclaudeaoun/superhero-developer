# Block Explorers

Every post, tip, trade and vote on Superhero is a public transaction, so you can check any of
them on an explorer. When something looks wrong, the explorer tells you whether the problem is
the chain or the app.

| Network | Explorer |
| --- | --- |
| Mainnet | `https://aescan.io` |
| Testnet | `https://testnet.aescan.io` |

æScan is built by æLabs and covers key blocks, micro blocks, accounts, transactions, contracts,
AENS names and AEX-9 tokens.

## URL shapes

Superhero links out to æScan wherever it shows an identifier — address chips, the post detail
view's tip overview, DEX activity and transaction cards, and the profile view. You can also
construct any link by hand:

| You have | URL | Page |
| --- | --- | --- |
| An account `ak_...` | `https://aescan.io/accounts/ak_...` | Account |
| A contract `ct_...` | `https://aescan.io/contracts/ct_...` | Smart Contract |
| A transaction `th_...` | `https://aescan.io/transactions/th_...` | Transaction |
| A name `nm_...` or `name.chain` | `https://aescan.io/names/...` | AENS Name |
| An oracle `ok_...` | `https://aescan.io/oracles/ok_...` | Oracle |

Swap the host for `testnet.aescan.io` to look at `ae_uat`. The name route takes either the name
itself or its `nm_` hash.

æScan indexes considerably more than Superhero links to:

| Path | What is there |
| --- | --- |
| `/keyblocks/<height>`, `/microblocks/<hash>` | Block detail, reachable from any transaction |
| `/tokens`, `/tokens/<ct_...>`, `/tokens/ae` | AEX-9 token list and holders, plus an AE page |
| `/nfts`, `/nfts/<id>` | AEX-141 tokens |
| `/state-channels`, `/state-channels/<id>` | Every channel on the network |
| `/oracles`, `/oracles/<ok_...>` | Oracle list and detail |
| `/dex-trades` | Exchange trades network-wide |
| `/contract-verification` | Submit source to verify a deployed contract |
| `/charts/...` | Accounts, contracts, difficulty, hashrate, keyblocks, names, price, transactions |
| `/mining`, `/nodes` | Network health |
| `/search/<term>` | Names, tokens and NFTs, as three tabs |

## Check that a transaction happened

Paste the `th_` into `aescan.io/transactions/`. The first panel is a flat table:

```text
Transaction ID · Transaction Type · Keyblock Height · Keyblock Confirmations
Status · Microblock Hash · Created · Fee · Nonce · API Links
```

- **Status.** A mined transaction can still have failed. Read this row, not just the presence of
  the transaction.
- **Keyblock Height and Keyblock Confirmations.** When, and how deeply buried. The height links to
  the keyblock page.
- **Transaction Type**, then the type-specific panel below it — for a contract call, the caller,
  the entrypoint and the decoded arguments.
- **API Links** gives you the middleware query behind the page.

If the hash returns nothing, the transaction is not on chain yet. Superhero treats a middleware
`404` as "still pending" rather than as an error; wait for a block before concluding anything.

## Check what a contract call did

Open `aescan.io/contracts/ct_...`. The header carries the contract's ID, type, create transaction,
creation height and time, creator, bytecode, account address, balance and call count; below it
are tabs for **Call Transactions** and **Events**, plus **Verification**, **Read Contract** and
**Write Contract** once a contract has been verified. æScan decodes the arguments, so you can
read the actual values a call was made with.

The same decoded data is available over HTTP. This is how the agent skill reads posts back out of
the Tipping contract:

```bash
curl "https://mainnet.aeternity.io/mdw/v3/transactions?contract=ct_2Hyt9ZxzXra5NAzhePkRsDPDWppoatVD7CtHnUoHVbuehwR8Nb&account=ak_...&limit=20"
```

Each returned transaction carries `tx.function` (the entrypoint called), `tx.arguments` (the
decoded argument list) and `tx.return` (the decoded result). The skill filters on
`tx.function === 'post_without_tip'` and reads the post text from `tx.arguments[0].value`.

## Check a token's sale contract

"The right token name" and "the right contract" are not the same thing. Before you spend:

1. On the token page, copy the sale address (`ct_...`).
2. Open `aescan.io/contracts/ct_...` and confirm it exists, is a contract, and has the call
   history a live sale should have.
3. Cross-check the address against a second source — the Superhero API's factory and token
   endpoints, or [Deployed addresses](/contracts/addresses) — rather than the page that showed it
   to you.

## The account page

`aescan.io/accounts/ak_...` opens on a table of **Address, Balance, Value, Transactions, Is
Generalized, Contract Id, Nonce** and **API Links**, with tabs for **Activities**,
**Transactions** and **AENS Names**.

- **Is Generalized** tells you whether the account is a generalized account with contract
  authentication rather than a plain keypair.
- **AENS Names** is the fastest way to see every `.chain` name an address owns.

## What else æScan shows

- **AENS.** Active `.chain` names, live auctions and recent registrations — the practical way to
  watch an auction you are bidding in. See [AENS](/aeternity/aens).
- **AEX-9 tokens.** Listed and unlisted tokens, with holder lists. See
  [AEX Standards](/aeternity/aex-standards).
- **State channels.** Active channels network-wide. See [State Channels](/aeternity/state-channels).
- **Network economics.** Circulating supply, burned coins, current block reward, plus the
  standalone charts under `/charts`.
