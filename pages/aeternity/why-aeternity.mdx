# Why æternity

Superhero is an on-chain social network: posts, comments, tips, token trades and votes are all
transactions. That only works if the chain underneath makes writing cheap, keeps identity native
to the protocol, and lets contracts verify user signatures. æternity provides all three.

## Cheap on-chain writes

Publishing every post on chain is only viable if a post costs a fraction of a cent. Approximate
costs on mainnet:

| Action | Approximate cost |
| --- | --- |
| Publish a post | ~0.00001 AE |
| Publish a comment | ~0.00001 AE |
| Cast a governance vote | ~0.0001 AE |
| Create a governance poll | ~0.01–0.02 AE, two transactions |
| Create a token | ~0.001 AE gas, plus any initial buy |

These are orders of magnitude, not protocol constants; gas price follows network demand. See
[AE & Gas](/aeternity/ae-and-gas) for how a fee is computed.

## Protocol-level names

`.chain` names are part of the protocol, not an application-level registry contract. A name
resolves the same way for every wallet and explorer on the network, so a Superhero display name
is portable rather than Superhero-specific. See [AENS](/aeternity/aens) and
[Chain names](/identity/chain-names).

## Native signature verification in contracts

Sophia exposes `Crypto.verify_sig`, and æternity defines a signed-message prefix
(`"aeternity Signed Message:\n"`, with a fixed 28-byte header) that a contract can reconstruct.
Superhero's Tipping and AddressLink contracts hash a message with Blake2b, prepend the prefix
to produce a 60-byte payload, and verify it with `Crypto.verify_sig`. That is what makes
[delegated posting](/social/delegated-posting) possible: a user signs off chain, a relayer pays
the gas, and the contract still attributes authorship to the signer.

## Sophia's safety properties

Sophia is strongly and statically typed with no mutable global state, which reduces the surface
for reentrancy and state-corruption bugs. See [Sophia & FATE](/aeternity/sophia-and-fate) and
[Contract security](/contracts/security).

## AEX-9 as the token standard

Every community token and the ProtocolDAO token is an AEX-9 fungible token, so third-party
wallets and explorers read Superhero balances without integrating with Superhero. See
[AEX Standards](/aeternity/aex-standards).

## What Superhero does not use

| æternity feature | Used by Superhero? |
| --- | --- |
| State channels | No. See [State Channels](/aeternity/state-channels). |
| Oracles | No. Superhero accepts and links `ok_` addresses but registers and queries no oracle. |
| Generalised accounts | No. |

Video calls at `/meet/:room` run on Jitsi, and chat runs on Nostr relays — neither is an
æternity layer-2 mechanism.
