# Smart Contracts

Every on-chain rule in Superhero lives in a Sophia contract running on the FATE virtual
machine. This section is the contract-level reference: what each contract does, the exact
signature of every entrypoint, the record and variant types you need to build arguments, the
events each one emits, and how to call all of it from JavaScript.

The signature tables are transcribed from the ACI (contract interface) JSON files vendored in
the agent skill under `superhero-agent-skill/contracts/`. Those files are authoritative for
entrypoint names, argument names, argument types, return types, and the `stateful` / `payable`
flags — they are the same files the SDK loads at runtime.

An ACI says nothing about **behaviour**, though: what a call requires, who may make it, what it
burns, and what it silently does not check. For that, these pages quote the Sophia itself. The
sources are `bcl-contracts/contracts/` for the token, DAO and affiliation suite,
`tipping-contract/contracts/v3/` for posting, and
`aepp-governance/governance-contracts/contracts/` for the polls. Two contracts have no source
in any repository reachable here — `FungibleTokenFull`, which is a pinned upstream dependency,
and `AddressLink`, which ships only as a compiled ACI. Both pages say so.

| Contract | Role | ACI vendored |
| --- | --- | --- |

| `CommunityFactory.aes` | Collections, community deployment, ProtocolDAO minting | `CommunityFactory.aci.json` |
| `AffiliationBondingCurveTokenSale.aes` | Buy/sell against the curve, affiliation fees | `AffiliationBondingCurveTokenSale.aci.json` |

| `BondingCurve.aes` | The curve interface the sale calls through | `BondingCurve.aci.json` |
| `DAO.aes` | One community treasury, vote creation and execution | inside `CommunityFactory.aci.json` |
| `DAOVote.aes` | One proposal and its locked stake | inside `CommunityFactory.aci.json` |
| `ReplaceableDAO.aes` | The interface a replacement DAO must implement | inside `CommunityFactory.aci.json` |
| `CommunityManagement.aes` | Moderators, write thresholds, community metadata | inside `CommunityFactory.aci.json` |
| `AffiliationTreasury.aes` | Referral accounting, invite codes, payouts | inside `CommunityFactory.aci.json` |
| `FungibleTokenFull.aes` | The AEX-9 token implementation | `FungibleTokenFull.aci.json` |
| `Registry.aes` / `Poll.aes` | æternity governance polls | `RegistryWithEventsACI.json`, `PollACI.json` |
| `AddressLink` | Identity: provider-keyed links from an address to an X handle, AENS name or nostr key | `superhero-api` `src/plugins/address-links/aci/AddressLink.aci.json` |

Several contracts have no ACI file of their own because the compiler inlines every contract
the factory references into `CommunityFactory.aci.json`. That single file therefore carries
`DAO`, `DAOVote`, `CommunityManagement`, `AffiliationTreasury`, `VoteSubjects`, `Set`, `Frac`
and `FungibleTokenFull` alongside `CommunityFactory` itself. When you need the DAO interface,
load the factory ACI.

## How the pieces fit together

```text
CommunityFactory                      one per network, deployed once
  ├── create_collection(...)          registers a naming namespace (555 AE, burned)
  └── create_community(...)           deploys four contracts in one transaction:
        ├── CommunityManagement       moderators, mute list, write threshold
        ├── DAO                       owner + beneficiary of the sale
        │     └── add_vote(...)       deploys a DAOVote (555 AE)
        └── AffiliationBondingCurveTokenSale
              ├── FungibleTokenFull   the community's AEX-9 token, created in the sale's init
              ├── buy                 mints tokens, splits the 1% spread
              └── sell                burns tokens, pays out AE
```

Three contracts sit outside that tree and are shared by every community:
`BondingCurveExponential`, which prices every trade and is never redeployed;
`AffiliationTreasury`, which accounts for referral rewards across all sales; and the
ProtocolDAO AEX-9 token, which the factory mints into every buyer's account.

`buy_with_affiliation` is not a user-facing alternative to `buy` — it is factory-only, used for
the creator's initial buy. An ordinary `buy` already credits the buyer's own referral chain. See
[AffiliationBondingCurveTokenSale](/contracts/token-sale).

## Why Sophia

Sophia is a strongly typed functional language in the ML family. It has no arbitrary mutable
global state — each contract has exactly one `state` value, replaced rather than mutated —
which removes whole classes of reentrancy and state-corruption bugs by construction. Every
FATE instruction is typed, and a type mismatch aborts the call and reverts all changes.

That is a real reduction in attack surface, but it is not a substitute for review. See
[Security Model](/contracts/security) for what has and has not been audited — the short
answer is that the public Sophia sources carry an explicit "not security audited" header.
