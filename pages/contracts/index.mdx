# Smart Contracts

Every on-chain rule in Superhero lives in a Sophia contract running on the FATE virtual
machine. These pages are the contract-level reference: what each contract does, the exact
signature of every entrypoint, the record and variant types you need to build arguments, the
events each one emits, and how to call all of it from JavaScript.

## The contract suite

| Contract | Role |
| --- | --- |
| [`Tipping.aes` (v3)](/contracts/tipping) | Post registry and delegated posting |
| [`CommunityFactory.aes`](/contracts/community-factory) | Collections, community deployment, ProtocolDAO minting |
| [`AffiliationBondingCurveTokenSale.aes`](/contracts/token-sale) | Buy and sell against the curve, affiliation fees |

| [`DAO.aes`](/contracts/dao) | One community's treasury, vote creation and execution |
| [`DAOVote.aes`](/contracts/dao-vote) | One proposal and its locked stake |
| `ReplaceableDAO.aes` | The interface a replacement DAO must implement |
| [`CommunityManagement.aes`](/contracts/community-management) | Moderators, write threshold, community metadata |
| [`AffiliationTreasury.aes`](/contracts/affiliation-treasury) | Referral accounting, invite codes, payouts |
| [`FungibleTokenFull.aes`](/contracts/aex9) | The AEX-9 token implementation |
| [`Registry.aes` / `Poll.aes`](/contracts/governance-contracts) | æternity governance polls |

`DAO`, `DAOVote`, `CommunityManagement`, `AffiliationTreasury`, `VoteSubjects`, `Set`, `Frac`
and `FungibleTokenFull` have no ACI file of their own: the compiler inlines them into
`CommunityFactory.aci.json`. Load the factory ACI when you need any of those interfaces.

## How the pieces fit together

```text
CommunityFactory                      one per network, deployed once
  ├── create_collection(...)          registers a naming namespace (555 AE, burned)
  └── create_community(...)           deploys four contracts in one transaction:
        ├── CommunityManagement       moderators, mute list, write threshold
        ├── DAO                       owner + beneficiary of the sale
        │     └── add_vote(...)       deploys a DAOVote (555 AE)
        └── AffiliationBondingCurveTokenSale
              ├── FungibleTokenFull   the community's AEX-9 token, created in the sale's init
              ├── buy                 mints tokens, splits the 1% spread
              └── sell                burns tokens, pays out AE
```

Three contracts sit outside that tree and are shared by every community:
`BondingCurveExponential`, which prices every trade; `AffiliationTreasury`, which accounts for
referral rewards across all sales; and the ProtocolDAO AEX-9 token, which the factory mints
into every buyer's account.

`buy_with_affiliation` is factory-only, used for the creator's initial buy. An ordinary `buy`
already credits the buyer's own referral chain. See
[AffiliationBondingCurveTokenSale](/contracts/token-sale).

## Sophia and FATE

Sophia is a strongly typed functional language in the ML family. A contract has exactly one
`state` value, replaced rather than mutated, so there is no partially updated storage for a
failed call to leave behind. Every FATE instruction is typed, and a type mismatch aborts the
call and reverts all changes. See [Sophia and FATE](/aeternity/sophia-and-fate).
