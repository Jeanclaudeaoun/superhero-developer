# How the Skill Works

The Superhero agent skill is a directory, not a service. Understanding its three layers — the
entry point, the playbooks and the executables — is what lets you extend it, audit it, or
replace the agent entirely and drive the scripts from cron.

## The three layers

| Layer | File(s) | Role |
| --- | --- | --- |
| Entry point | `SKILL.md` | What the agent reads first: capabilities table, workflows, security rules |
| Playbooks | `guides/*.md` | Task-specific instructions the agent reads on demand |
| Executables | `scripts/*.mjs` | Plain Node scripts that do the on-chain work and print JSON |

Two supporting directories complete the picture:

| Directory | Contents |
| --- | --- |
| `contracts/` | Nine JSON files: contract ACIs plus `PollBytecode.json`, the compiled Poll contract the governance script deploys |
| `package.json` | Two runtime dependencies and a `skill` block declaring the install command and the required environment variable |

## The frontmatter schema, field by field

`SKILL.md` opens with YAML frontmatter. Two fields are required by the
[Agent Skills specification](https://agentskills.io/specification); the third is a
runtime-specific extension.

```yaml
---
name: superhero
description: Superhero.com social network agent — post tamperproof content, create tokens, and trade trending tokens on æternity blockchain. Autonomous mode available with configurable risk strategies and cron scheduling.
metadata:
  {
    "openclaw":
      {
        "requires": { "env": ["AE_PRIVATE_KEY"] },
        "primaryEnv": "AE_PRIVATE_KEY",
        "install":
          [
            {
              "id": "npm",
              "kind": "node",
              "package": "@aeternity/aepp-sdk",
              "label": "Install dependencies (npm)",
            },
            {
              "id": "npm",
              "kind": "node",
              "package": "bignumber.js",
              "label": "Install dependencies (npm)",
            },
          ],
      },
  }
---
```

| Field | Type | What it does |
| --- | --- | --- |
| `name` | string | The skill's identifier, `superhero`. Under the Agent Skills standard this must match the containing folder's name, which is why the install instructions all clone into a directory called `superhero` rather than `superhero-agent-skill` |
| `description` | string | The trigger text. Runtimes keep this in context permanently and load the full `SKILL.md` only when a request matches it. It names the four capabilities — posting, token creation, trading, autonomous mode with cron — so that a request mentioning any of them routes here |
| `metadata` | mapping | Free-form runtime extensions. Runtimes that do not recognise a key ignore it |
| `metadata.openclaw.requires.env` | array of strings | Environment variables the skill cannot run without. One entry: `AE_PRIVATE_KEY` |
| `metadata.openclaw.primaryEnv` | string | The single variable the runtime should prompt for at install time. Also `AE_PRIVATE_KEY` |
| `metadata.openclaw.install` | array of objects | Install steps the runtime can execute on the operator's behalf. Each has an `id`, a `kind` (`node`), a `package`, and a human-readable `label`. Two entries, one per npm dependency |

The same two dependencies are declared a second time, canonically, in `package.json`, which
also carries a parallel `skill` block:

```json
{
  "skill": {
    "install": "npm install",
    "env": {
      "AE_PRIVATE_KEY": {
        "required": true,
        "description": "æternity wallet private key used to sign all on-chain transactions (posts, trades, token creation, invites). Set via: export AE_PRIVATE_KEY=<key>"
      }
    }
  }
}
```

Two declarations of the same contract is redundant but harmless: a runtime that understands
neither block still works, because `npm install` in the skill directory resolves the
`dependencies` field like any Node project.

### Which runtimes read which block

The `metadata` mapping is the standard's escape hatch, and what a runtime does with the keys
inside it is entirely that runtime's business.

| Runtime | What it reads |
| --- | --- |
| OpenClaw / ClawHub | The `metadata.openclaw` block. `requires.env`, `requires.bins`, `primaryEnv` and `envVars` are documented fields of ClawHub's skill format, and its security analysis flags a skill whose code reads an environment variable the frontmatter does not declare |
| GitHub Copilot | `name`, `description`, `allowed-tools`, and a `metadata` section it uses for its own purposes — a version field, and the provenance `gh skill` writes on install. **No environment declaration at all**, so nothing prompts for `AE_PRIVATE_KEY` |
| Claude Code | `name` and `description` for discovery. It has its own permission system rather than an env declaration |

The practical rule: **assume nothing prompts you.** Set `AE_PRIVATE_KEY` yourself before the
first run, on every runtime, and verify with `superhero-wallet.mjs exists` as the first thing
you ask for. The `package.json` `skill.env` block is the runtime-agnostic place to look for
the same information if you are adapting the skill somewhere new.

## The `{baseDir}` placeholder

Every command inside `SKILL.md` and the guides is written with a `{baseDir}` prefix:

```bash
node {baseDir}/scripts/superhero-wallet.mjs balance
```

`{baseDir}` is not shell syntax and not an environment variable. It is a placeholder the
runtime substitutes with the absolute path of the installed skill directory before the text
reaches the model. An agent that has loaded the skill from
`/home/you/.claude/skills/superhero` sees:

```bash
node /home/you/.claude/skills/superhero/scripts/superhero-wallet.mjs balance
```

Two consequences matter in practice:

1. **If your runtime does not perform the substitution, the commands will not run.** The model
   will emit `node {baseDir}/scripts/...` literally and the shell will fail. Resolve the paths
   yourself, or `cd` into the skill directory and use the relative form
   `node scripts/superhero-wallet.mjs balance`, which is what the `guides/governance.md`,
   `guides/trading.md` and `guides/portfolio.md` examples already use.
2. **Substituting the path is not the same as setting the working directory.** Five scripts
   load their contract ACIs with a *cwd-relative* path, `./contracts/...`. Running
   `node /abs/path/to/superhero/scripts/superhero-post.mjs "hi"` from your home directory
   fails with `ENOENT` even though the script path was resolved correctly.

## The working-directory contract

| Script | Reads `contracts/` how | Safe to run from anywhere? |
| --- | --- | --- |
| `superhero-post.mjs` | `./contracts/Tipping_v3.aci.json` | No |
| `superhero-comment.mjs` | `./contracts/Tipping_v3.aci.json` | No |
| `superhero-token-swap.mjs` | `./contracts/AffiliationBondingCurveTokenSale.aci.json`, `./contracts/FungibleTokenFull.aci.json` | No |
| `superhero-token-create.mjs` | `./contracts/CommunityFactory.aci.json`, `./contracts/BondingCurve.aci.json` | No |
| `superhero-invite.mjs` | `./contracts/CommunityFactory.aci.json` | No |
| `superhero-governance.mjs` | Resolved from the script's own location | Yes |
| The other six | No contract files | Yes |

The rule that always works: `cd` into the skill root first.

## The script conventions

Every script in `scripts/` follows the same five conventions. They are what make the skill
runtime-agnostic.

1. **One file, one domain, `main()` with a `switch`.** The first CLI argument selects a
   `case`. Unrecognised arguments fall through to a `help` block.
2. **Structured output on stdout.** Results are `JSON.stringify`'d and printed with
   `console.log`. Nothing else is written to stdout.
3. **Human progress on stderr.** Lines like `Posting "..." with 0 link(s)...` and
   `Step 1/3: Preclaiming ...` go to `console.error`, so `stdout` stays machine-parseable even
   during long multi-transaction flows. Pipe stdout to `jq` and leave stderr on the terminal.
4. **The key comes from the environment, once.** Each script has its own `loadAccount()` or
   `loadAddress()` reading `process.env.AE_PRIVATE_KEY`. No script writes it anywhere, and no
   script prints it — except `superhero-wallet.mjs generate` and `import`, whose entire purpose
   is to show it to you.
5. **Non-zero exit on failure.** Every script ends with a `.catch` that prints the message to
   stderr and calls `process.exit(1)`.

Nothing in the scripts is model-specific. There is no prompt, no LLM call, no API key beyond
the wallet. The "agent" part lives entirely in the markdown.

## How the agent picks a guide

`SKILL.md` contains a capabilities table mapping each task to a guide path and a one-line
example command:

| Task | Guide | Quick command |
| --- | --- | --- |
| Post | `guides/posting.md` | `superhero-post.mjs "message"` |
| Read posts | `guides/posting.md` | `superhero-read.mjs my-posts` |
| Comments | `guides/commenting.md` | `superhero-comment.mjs post <post_id> "text"` |
| Create token | `guides/token-creation.md` | `superhero-token-create.mjs create "NAME" 0.1` |
| Buy/sell tokens | `guides/trading.md` | `superhero-token-swap.mjs buy ct_... 5` |
| Trending | `guides/trading.md` | `superhero-trending.mjs tokens 10` |
| Holdings and history | `guides/portfolio.md` | `superhero-portfolio.mjs holdings` |
| Transactions | `guides/portfolio.md` | `superhero-transactions.mjs token ct_...` |
| Invite links | (inline in `SKILL.md`) | `superhero-invite.mjs generate 1 5` |
| Wallet and balance | `guides/setup.md` | `superhero-wallet.mjs balance` |
| Names (AENS) | (inline in `SKILL.md`) | `superhero-name.mjs register myagentname` |
| Autonomous mode | `guides/autonomous.md` | configured via cron and a strategy |
| Governance polls | `guides/governance.md` | `superhero-governance.mjs list` |

The instruction under the table is explicit: *read the relevant guide for detailed
instructions before executing a task.* This is progressive disclosure. Only `SKILL.md` — about
12 KB — is in context by default; the guide for the task at hand is pulled in on demand. Two
capabilities, invites and AENS names, have no guide file and are documented inline in
`SKILL.md` instead.

`SKILL.md` also hard-codes four multi-step workflows that the agent must follow rather than
improvise: first-run setup detection, token creation, governance poll creation, and the
autonomous-versus-manual mode question. Each is a numbered checklist with a mandatory user
confirmation in the middle.

## Adding a script of your own

To extend the skill without forking its design:

1. **Write `scripts/superhero-<domain>.mjs`** as an ES module (`package.json` sets
   `"type": "module"`). Follow the five conventions above — especially JSON on stdout and
   `process.exit(1)` on failure.
2. **Resolve contract paths from the script's own location,** the way
   `superhero-governance.mjs` does, rather than from the cwd:

   ```js
   import { fileURLToPath } from 'url';
   import path from 'path';
   const __dirname = path.dirname(fileURLToPath(import.meta.url));
   const CONTRACTS_DIR = path.join(__dirname, '..', 'contracts');
   ```

3. **Add a `help` case.** It is the only interface an unfamiliar agent has to your script.
4. **Add a row to the capabilities table in `SKILL.md`,** and a guide in `guides/` if the task
   needs more than one command. The agent will not find a script that is not in the table.
5. **Drop any new ACI into `contracts/`.** The existing ACIs are exported from the Superhero
   contract sources — see [Calling contracts](/contracts/calling-contracts).

If you need a network other than mainnet, note that only `superhero-governance.mjs` honours an
`AE_NODE_URL` override. The other eleven scripts hard-code
`https://mainnet.aeternity.io`.
