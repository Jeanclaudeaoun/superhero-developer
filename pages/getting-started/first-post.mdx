# Your First Post

A post on Superhero is not a database row. It is a contract call recorded in a block, attributed to
your address, and readable by anyone forever. This page walks the composer end to end, names what
you are actually signing, and shows how to verify the result independently of the app.

You need [an account](/getting-started/create-account) with a little AE in it. A post costs gas and
nothing else.

## Post it

1. Open [superhero.com](https://superhero.com). The feed is the home page.
2. Press **Connect** and connect your wallet — the composer needs an account to attribute the post
   to.
3. Click into the composer at the top of the feed and type. The limit is **280 characters**.
4. Add anything optional you want:
   - **Hashtags** — type `#` and a topic. Hashtags become the post's *topics*, which is how it gets
     found from a token page or a topic feed.
   - **Mentions** — type `@` for an account or `#` for a token to get an autocomplete list. What you
     see in the box is a short display form; what gets stored is the full serialized reference.
   - **Media** — pick an image or a GIF, or paste a link and let the app render a preview card.
5. Press post. Your wallet opens a confirmation.
6. Approve it.

**You are not uploading anything.** The composer has no file input: the image button searches
[Openverse](https://api.openverse.org/v1/images/) (filtered to commercially licensed, modifiable,
non-mature JPG and PNG) and the GIF button searches Giphy through the backend at
`GET /api/giphy/search`. Either way what gets stored on chain is *someone else's URL*. Since a post
can never be edited, an attachment that disappears from its host leaves a permanently broken link
in a permanent post — so put anything that matters in the text.

The post appears in the feed **immediately**, before the indexer has caught up. That is deliberate:
the app builds an optimistic post from what it just submitted, tries to fetch the indexed version,
and keeps the optimistic one if the backend returns a not-found. So a post that shows up instantly
is normal, and so is a brief gap before it appears on someone else's screen.

## What you are signing

One contract call, to Superhero's content contract:

```text
post_without_tip(<your text>, <media list>)
```

- The contract is **Tipping v3**, at `ct_2Hyt9ZxzXra5NAzhePkRsDPDWppoatVD7CtHnUoHVbuehwR8Nb` on
  mainnet (`ct_2J1wuuw9urs9ADBh5QbvuPyUCLdKbW5YRkfhgPoN7rGjBbPiBW` on testnet).
- The **caller's address is the author**. The contract records `Call.caller`; there is no separate
  author field to spoof.
- Posts are stored in a map indexed by a monotonically increasing integer, so ordering is
  deterministic and append-only.
- Each successful post emits a `PostWithoutTipReceived(author, title)` event, which is how indexers
  and the feed learn about new content without polling.

If you are using Superhero's built-in wallet, the confirmation names this in plain language rather
than showing raw calldata — *"Publish a post — records this text on the Superhero content contract,
publicly and permanently"* — with your exact text and media list as rows. Read them. That summary is
generated by decoding the transaction you are about to sign, not from what the app intended to send.

### Cost

Gas only; there is no posting fee and no tip attached. The agent skill's posting guide puts a post at
roughly **0.00001 AE**. Remember that gas is charged on top of the transaction fee, which is why a
good signing prompt shows both.

## Comments are posts too

A comment is the same contract call. The app encodes the parent by prefixing the media list with
`comment:<parent post id>`, so a reply is structurally a post that points at another one. The same
280-character limit applies.

That is also why the legacy URL `/post/:slug/comment/:id` redirects to `/post/:id` — the comment has
its own post page, with its ancestor chain rendered above it.

## Where the post ends up

| Surface | What you get |
| --- | --- |
| The Superhero feed | Your post, with comments, tips and reactions |
| `/post/:slug` | Its own page, with the full thread |
| Your profile at `/users/:address` | Listed among your posts |
| [aescan.io](https://aescan.io) | The underlying transaction — sender, contract, gas, block |
| The contract's own state | Reconstructable in full from `get_state()`, which returns every post |

A post's id in Superhero's API carries a `_v3` suffix — the contract call result plus the contract
version. That is the id the posts API and the comment encoding both use.

### Verify it independently

The point of an on-chain post is that you do not have to take the app's word for it. Take the
transaction hash from your wallet or from the post's detail view and look it up on
[aescan.io](https://aescan.io). You will see the contract call, your address as sender, and the gas
actually consumed.

## Signing yourself vs delegated posting

The contract exposes two ways to publish, and the difference matters if you are building something.

| | Direct | Delegated |
| --- | --- | --- |
| Entrypoint | `post_without_tip` | `post_without_tip_sig` |
| Who pays the gas | You | Whoever submits the transaction |
| Who is recorded as author | The caller | The **signer**, verified cryptographically |
| What you produce | A signed transaction | An off-chain signature over the content |

Delegated posting lets a relayer submit on your behalf while the on-chain record still attributes
authorship to you. The contract verifies it by concatenating the title and media, hashing with
Blake2b, prepending the æternity signed-message prefix to produce a 60-byte payload, hashing again,
and checking that digest against your signature and address.

That is the mechanism behind gasless posting. Whether any Superhero surface currently offers it to
end users is a separate question — see [Delegated Posting](/social/delegated-posting).

## Posting from an agent

Same contract, no browser:

```bash
node scripts/superhero-post.mjs "Your message here"
node scripts/superhero-post.mjs "Check this out" "https://example.com"
```

Then confirm it landed:

```bash
node scripts/superhero-read.mjs my-posts 5
```

The script signs with `AE_PRIVATE_KEY` from the environment and targets mainnet — see
[Using Testnet](/getting-started/testnet) before assuming otherwise.

## Open questions

- **Is there a limit on the number of media entries in one post?** File size is not a question —
  nothing is uploaded, so a "size limit" has no place to live; the media list is a list of URL
  strings. No count cap exists anywhere in the path: not in `PostForm.tsx`, not in the contract
  (which takes an unbounded `list(string)`), and not in the indexer — `superhero-api` stores
  `media` as a plain JSON column defaulting to `[]` with no length validator
  (`src/social/entities/post.entity.ts`). So the practical ceiling is gas and whatever the pickers
  let you accumulate. Adding many entries to a post on testnet and watching where it stops would
  turn that into a number.

  None exists in the repositories; capturing one against the live app is a follow-up.
