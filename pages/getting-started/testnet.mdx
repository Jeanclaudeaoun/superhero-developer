# Using Testnet

æternity's public testnet (`ae_uat`) is where you experiment without spending real AE. Superhero has
a complete second deployment there — its own backend, its own contracts, its own explorer. This page
has the endpoints, the contract addresses, how to get test AE, and an honest account of which tools
can actually be pointed at testnet.

## Network selection is a build-time decision

Superhero builds are **pinned to one network when they are built**, through the `VITE_NETWORK`
environment variable. It accepts `ae_mainnet` (the default) or `ae_uat`; anything else falls back to
mainnet.

There is no in-app network switcher. The running app offers exactly one network, and a wallet on the
other one produces a mismatch you resolve in the wallet. To use testnet you need a testnet build:

```bash
VITE_NETWORK=ae_uat npm run dev
VITE_NETWORK=ae_uat npm run build
```

If you are also testing passkeys on that build, set the WebAuthn Relying Party ID to match your
origin at the same time, or passkey registration fails silently:

```bash
VITE_NETWORK=ae_uat VITE_WEBAUTHN_RP_ID=localhost npm run dev
```

See [Troubleshooting](/wallets/troubleshooting) for why that failure is invisible.

## Getting test AE

Use the æternity faucet at **[faucet.aepps.com](https://faucet.aepps.com/)**: select Testnet, paste
your `ak_...` address, and submit. The form takes nothing but the address. It also has a programmatic
form:

```bash
curl -X POST https://faucet.aepps.com/account/ak_YOUR_ADDRESS
```

**There is a per-address cooldown, and it is enforced with a distinctive status code.** Request again
too soon and the faucet answers **HTTP 425** with a message of the form "The address is graylisted
for another …". Handle 425 explicitly in any script that tops an account up — it is not a failure,
it is a wait.

The grant amount is the one figure not to hard-code: published sources report both 5 AE and 250 AE
for different faucet deployments, and the amount has changed over the project's life. Read what the
faucet actually returns rather than assuming — see the open questions.

Test AE has no value and is not convertible to mainnet AE. If you need more than a single grant,
wait out the graylist and request again, or run your own faucet from
[aeternity/aepp-faucet](https://github.com/aeternity/aepp-faucet), where the top-up amount is a
configuration value you control.

The faucet's own documentation is at
[Testnets and Faucet](https://docs.aeternity.com/aeternity-developer-tools/development-infrastructure/testing-and-deployment/testnets-and-faucet)
on the æternity docs hub.

## Pointing a wallet at testnet

Superhero Wallet — extension, mobile or web — supports switching to testnet in its own network
settings. Because the app is build-pinned, the two must agree: a mainnet build plus a testnet wallet
produces a mismatch the app cannot fix for you.

## The agent skill is mainnet-only

This is the caveat worth stating plainly rather than burying.

**The agent-skill scripts hardcode mainnet endpoints.** Every script in
`superhero-agent-skill/scripts/` except one sets its node and API URLs as constants at the top of the
file:

| Script | Hardcoded |
| --- | --- |
| `superhero-wallet.mjs` | `https://mainnet.aeternity.io` |
| `superhero-post.mjs` | `https://mainnet.aeternity.io` |
| `superhero-comment.mjs` | `https://mainnet.aeternity.io`, `https://api.superhero.com` |
| `superhero-name.mjs` | `https://mainnet.aeternity.io`, `https://mainnet.aeternity.io/mdw/v3` |
| `superhero-invite.mjs` | `https://mainnet.aeternity.io` |
| `superhero-token-create.mjs` | `https://mainnet.aeternity.io`, `https://api.superhero.com` |
| `superhero-token-swap.mjs` | `https://mainnet.aeternity.io`, `https://api.superhero.com` |
| `superhero-read.mjs` | `https://mainnet.aeternity.io/mdw/v3` |
| `superhero-portfolio.mjs` | `https://api.superhero.com` |
| `superhero-trending.mjs` | `https://api.superhero.com` |
| `superhero-transactions.mjs` | `https://api.superhero.com` |

The single exception is `superhero-governance.mjs`, which reads `AE_NODE_URL` from the environment
and falls back to mainnet:

```bash
AE_NODE_URL=https://testnet.aeternity.io node scripts/superhero-governance.mjs ...
```

There is **no environment variable that repoints the rest of them.** Running the skill against
testnet today means editing the constants at the top of each script you need, and also swapping the
Superhero API base — the testnet backend is `https://testnet.api.dev.tokensale.org`, which is a
different host rather than a path on the same one.

Treat every agent-skill command in these docs as a **mainnet command spending real AE** unless you
have changed those constants yourself.

## Is there a hosted testnet front end?

Probably, but no public URL for it is recorded anywhere, and you should plan on building your own.

What is established: **the testnet backend is real and deliberately operated.** The API repository
treats `testnet` as one of four named deploy environments in its workflow (alongside `develop`,
`staging` and `production`), and ships a `docker-compose-testnet.yml` that names a
`superhero-api-testnet2` container and a matching `.env.testnet.example`. That is consistent with
`https://testnet.api.dev.tokensale.org` in `src/config.ts` being a live service rather than a
leftover.

What is not established is a testnet build of the **web app**. No `testnet.superhero.com` or
equivalent appears in any repository, the deploy hosts in the workflow are GitHub secrets, and the
app's own config never refers to a testnet front-end origin. So assume you build it:

```bash
VITE_NETWORK=ae_uat npm run dev
```

## Open questions

- **What is the faucet's grant per request?** Published figures disagree — 5 AE and 250 AE both
  appear for different æternity faucet deployments — and the amount is a configuration value, not a
  protocol constant, so any number written here would be a guess about someone's deployment. The
  rate limit *shape* is settled (a per-address graylist, signalled by HTTP 425), but not its
  duration. Both close in one request: `POST https://faucet.aepps.com/account/<address>` and read
  the response, then repeat it and read the graylist message. Outbound HTTP is blocked in the
  environment these docs were written in, so neither call could be made.
- **Is a public testnet deployment of the Superhero front end hosted anywhere?** See above — the
  testnet *backend* is evidently operated, but no front-end URL exists in any repository. Only
  Superhero can say whether one is published.

The `disabled: true` flag on the mainnet network entry is no longer an open question: it is
vestigial and inert, and [Networks & Endpoints](/aeternity/networks) traces it end to end.
