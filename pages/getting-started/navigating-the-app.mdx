# Navigating the App

superhero.com is a single-page app with a flat route table. This page is that table, verified
against `src/routes.tsx`, plus the redirects you will hit from older links and a note on what
actually requires a wallet.

## How wallet access works

**No route on superhero.com is gated behind a wallet.** There are no protected routes in the router —
every page renders, and every page that needs an account shows a Connect control in place of the
action rather than refusing to load. The token creation page, for example, renders its whole form
and swaps the submit button for **Connect wallet to create**.

So the "Wallet" column below means *the primary action here needs a connected account*, not *this URL
is blocked*. Browsing is always open.

## Social

| Path | What it is | Wallet |
| --- | --- | --- |
| `/` | The social feed | To post, comment or tip |
| `/post/:slug` | A single post and its comment thread | To comment or tip |
| `/users/:address` | A user profile | To edit your own |
| `/profile/x/callback` | OAuth landing page for the Connect X flow | Part of a signed flow |

`:slug` also accepts a post id; `PostDetail` redirects to the canonical slug.

## Trends and tokens

| Path | What it is | Wallet |
| --- | --- | --- |
| `/trends/tokens` | Trending community tokens | No |
| `/trends/tokens/:tokenName` | A token page: feed and chat, trade card, info, transactions, holders | To trade |
| `/trends/create` | Create a new community token | **Yes** |
| `/trends/daos` | All community DAOs | No |
| `/trends/dao/:saleAddress` | One community's DAO | To propose or vote |
| `/trends/dao/:saleAddress/vote/:voteId/:voteAddress` | A single DAO vote | To vote |
| `/trends/accounts` | Trader and creator accounts | No |
| `/trends/accounts/:address` | One account's tokens, creations and activity | No |
| `/trends/leaderboard` | Leaderboards | No |
| `/trends/invite` | Invite links and the affiliate program | **Yes** |
| `/trends/visx` | The trend cloud visualisation | No |
| `/trends` | Redirects to `/trends/tokens` | — |

Note the singular/plural split, which is easy to get wrong when writing links: the **list** is
`/trends/daos`, a **single DAO** is `/trends/dao/:saleAddress`. The parameter is a **sale address**,
not the AEX-9 token address.

## Chat

| Path | What it is | Wallet |
| --- | --- | --- |
| `/chat` | Chat inbox — all, communities and DMs | **Yes** |
| `/chat/:saleAddress` | A token-gated community room | **Yes** |
| `/chat/:saleAddress/info` | Room info and members | **Yes** |
| `/chat/dm/:address` | A direct-message thread | **Yes** |
| `/chat/settings/relays` | Relay configuration | **Yes** |

Chat identity is derived from your wallet, so chat needs one throughout. The two-segment literal
paths (`dm/…`, `settings/relays`) are ordered so they can never collide with the one-segment room
parameter.

## Redirects

Old links keep working. Every one of these is a real route that redirects:

| From | To |
| --- | --- |
| `/trending`, `/trending/tokens` | `/trends/tokens` |
| `/trending/visx`, `/trending/invite`, `/trending/daos`, `/trending/accounts`, `/trending/create`, `/trending/leaderboard` | the matching `/trends/*` path |
| `/trending/tokens/:tokenName` | `/trends/tokens/:tokenName` |
| `/trending/dao/:saleAddress` and its vote path | the matching `/trends/dao/*` path |
| `/trending/accounts/:address` | `/trends/accounts/:address` |
| `/user/:address` | `/users/:address` |
| `/post/:slug/comment/:id` | `/post/:id` — a comment is itself a post |
| `/buy-ae` | `/get-ae` |
| `/swap` | `/defi/swap` |

Legacy DEX paths that still render their own view rather than redirecting: `/pool`, `/explore`,
`/explore/tokens/:id`, `/explore/pools/:id` and `/pool/add-tokens`.

Anything else renders the not-found page.

## Development-only routes

`/wallet-lab` exists only in development builds. It clears and rewrites the real on-device vault
store, so it is guarded by a build-time flag and eliminated entirely from production output. You will
not find it on superhero.com.

## Open questions

- A screenshot per major section would make this page substantially easier to use. None is included
  here because none exists in the repository; capturing them against the live app is a follow-up.
- **Do the native mobile apps use the same route paths, or a different navigation model?** The web
  routes in `src/routes.tsx` are authoritative for superhero.com, and no repository describes the
  native apps' navigation. Nothing in the app distinguishes native from PWA — the surface-gated
  behaviours it does have key on *installed versus browser tab* — which is suggestive of a shared
  route table but is not evidence of one. Someone with the native app installed would have to
  compare, or Superhero would have to say whether the store builds wrap the same web routes.
