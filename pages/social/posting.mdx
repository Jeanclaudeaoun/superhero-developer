# Posting

A Superhero post is a contract call. The text and any attached media go into the `Tipping` v3
contract's state, the caller's address is recorded as the author, and the contract returns an
integer id. There is no edit and no delete — not as a policy, but because the contract exposes
no entrypoint that could do either. This page covers the data model, the call, the encoding
conventions the app layers on top, the cost, and both the UI and CLI paths.

## The data model

Each post is a `PostWithoutTip` variant holding structured metadata and a list of media
strings:

| Field | Type | Meaning |
| --- | --- | --- |
| `tip_meta.sender` | `address` | The author — the account whose signature authorised the post |
| `tip_meta.title` | `string` | The post's text content |
| `tip_meta.timestamp` | `int` | `Chain.timestamp` at the moment of posting |
| `media` | `list(string)` | Media URLs or identifiers attached to the post |

Posts live in a map keyed by a monotonically increasing `tip_id`, giving a deterministic,
append-only ordering of everything ever published through the contract. The contract's state
record is just that map plus a `version` string, currently `"v3"`.

The field is called `title` for historical reasons. It holds the whole post body, not a
headline.

## Contract entrypoints

The full Tipping v3 surface, read from `tipping-contract/contracts/v3/Tipping_v3.aes`, is four
entrypoints. None of them is `payable`:

| Entrypoint | Signature | Stateful | Purpose |
| --- | --- | --- | --- |
| `init` | `() => Tipping.state` | no | Deployment |
| `post_without_tip` | `(title: string, media: list(string)) => int` | yes | Direct posting; `Call.caller` is the author |
| `post_without_tip_sig` | `(title: string, media: list(string), author: address, sig: signature) => int` | yes | Delegated posting on behalf of a signer |
| `get_state` | `() => Tipping.state` | no | Read the whole post history |

Both posting entrypoints return the new `tip_id` and emit
`PostWithoutTipReceived(address, string)` — the author and the title — so indexers can follow
new content without polling state.

Note what is **not** there: despite the contract's name, Tipping v3 has no tipping entrypoint.
Tips are plain AE transfers with a payload; see [Tipping](/social/tipping).

## Post ids and slugs

The contract returns a bare integer. The indexer forms the API id as the contract's return
value plus `_v` plus the contract's configured version — `_v3` today — so a post created as
`3903` is referenced everywhere as `3903_v3`. If the middleware hands the indexer a transaction
with no return value, it falls back to the **last eight characters of the transaction hash**
plus the same suffix, which is why an occasional id is not numeric.

In-app links then drop the suffix again: a post link is `/post/` plus the id with `_v3`
stripped, or a human-readable slug the API generates for SEO. The resolver at `/post/:slug`
tries, in order:

1. `GET /api/posts/` with the key exactly as given — this handles slugs.
2. If the key is numeric or already ends in `_v3`, retry with `_v3` appended.
3. Fall back to `GET /api/posts?search=…&limit=1&page=1` and fetch by the returned `id`.

Write the suffix when you call the API and drop it when you build a URL, and the round trip
works from either direction.

The slug itself is derived once, at index time, from the post's own text
(`superhero-api/src/social/services/post.service.ts`):

```text
base = content.toLowerCase()
             .replace(/[^\p{L}\p{N}._~-]+/gu, '-')   // any non-word run becomes one hyphen
             .replace(/-+/g, '-')
             .replace(/^-+|-+$/g, '')
             .slice(0, 60)
slug = (base ? base + '-' : '') + <the numeric part of the id>
```

So `"Hello, æternity!"` as post `3903_v3` becomes `hello-æternity-3903`. Letters and digits in
any script survive; the id suffix makes the slug unique even when two posts normalise
identically. Slugs are never regenerated, so editing is moot — there is no edit.

## Content encoding

The contract stores a string. Everything below is a client-side convention the indexer and the
renderer agree on — the contract neither knows nor enforces any of it.

| Convention | Written as | Meaning |
| --- | --- | --- |
| Account mention | `[account:ak_…]` | A tagged account. The composer shows a short display run and expands it to this macro on submit. |
| Token tag | `#SYMBOL` | A hashtag that resolves to a community token when one exists. |
| Token display envelope | `#SYMBOL{mode=advanced}` | An optional suffix asking for a richer rendering. The symbol is never modified. |
| Comment marker | `comment:<parent post id>` | First entry in `media`, marking the post as a reply. |

The account-mention macro is a pure client contract: the API does not index raw `ak_` mentions,
and a bare address in the text renders as a plain link. The token-tag envelope is permissive to
write and strict to read — an unparseable payload falls back to the plain tag rather than
rendering as text, so nothing already on chain can be broken by a future syntax change. See
[Hashtags & Topics](/social/hashtags-and-topics) for the envelope's option grammar.

## Limits

There are three layers and they do not agree. The contract accepts anything; the composer is
strict; the indexer sits in between and quietly rewrites what it stores.

| Limit | Value | Enforced by |
| --- | --- | --- |
| Character count, composer | 280 | The web composer, for posts and comments alike |
| Character count, indexed copy | 5,000 | `sanitizeContent` in the indexer — longer content is **truncated**, not rejected |
| Character count, on chain | Unbounded | The contract stores whatever string you pass |
| Media entries, indexed | 5 | `extractMedia` keeps the first five valid entries and drops the rest |
| Media entries, on chain | Unbounded | The contract stores the whole list |
| Topics per post | 10 | `extractTopics`, each at most 50 characters after normalization |
| Editing | Impossible | The contract has no update entrypoint |
| Deletion | Impossible | The contract has no delete entrypoint |

The 280-character limit is a client-side constant. A post written through the SDK or the CLI is
not bound by it, but the copy the API serves is normalised on the way in
(`superhero-api/src/social/utils/content-parser.util.ts`):

- trimmed;
- CRLF converted to LF;
- three or more consecutive newlines collapsed to two;
- truncated to 5,000 characters.

So a 6,000-character post is on chain in full and truncated everywhere a reader will see it.
Read it back from the contract if you need the original.

### What counts as a media entry

`extractMedia` does not store the `media` list verbatim. Each entry must be a parseable URL
with an `http:` or `https:` scheme, and must either end in `.jpg`, `.jpeg`, `.png`, `.gif`,
`.webp`, `.mp4`, `.webm` or `.mov`, or be hosted on `imgur.com`, `giphy.com`, `youtube.com` or
`vimeo.com` (or a subdomain of one). Everything else is dropped from the indexed `media` array,
and only the first five survivors are kept.

That rule is why a comment's `comment:3903_v3` marker never appears in the API's `media` field
even though it is the first entry on chain: it is not a URL, so it is filtered out. The
`tx_args` field still carries the raw list, which is where the client's parser looks.

The same convention has one more hook: if any raw media entry contains the substring `hidden`,
the indexer sets `posts.is_hidden = true`, which removes the post from the feeds and from
popular ranking. It is a self-applied flag, not a moderation control — see
[Moderation](/social/moderation).

## Posting from the app

Compose at the top of the feed at `https://superhero.com/`, or from a token's topic tab where
the composer requires that token's hashtag before the Post button enables. On submit the app:

1. Expands tagged mentions from their display form to the `[account:…]` storage form.
2. Builds the `media` list — attached URLs for a post; `comment:` plus the parent id first for
   a reply.
3. Initialises the contract with the vendored ACI and `CONTRACT_V3_ADDRESS`.
4. Calls `post_without_tip(content, media)` through the connected wallet.
5. Suffixes the returned id with `_v3`, optimistically inserts the post into the feed cache,
   and reconciles against `GET /api/posts/` once the backend has indexed it.

The optimistic insert is why a new post appears instantly even though the indexer has not seen
it yet. If the backend 404s on the first fetch, the app keeps its own optimistic copy and
retries.

## Posting from the command line

The agent skill wraps the same call. It needs `AE_PRIVATE_KEY` in the environment and posts to
mainnet.

```bash
node scripts/superhero-post.mjs "Your message here"
node scripts/superhero-post.mjs "Check this out" "https://example.com"
node scripts/superhero-post.mjs "Multiple links" "https://link1.com" "https://link2.com"
```

Every argument after the first becomes a `media` entry. The script prints JSON:

```json
{
  "success": true,
  "post_id": "3903",
  "content": "Your message here",
  "links": [],
  "tx_hash": "th_..."
}
```

Note that `post_id` here is the bare integer — add `_v3` before you look it up through the API.

## Posting with the SDK directly

Illustrative shape, matching what both the app and the CLI do:

```js
import { AeSdk, Node, MemoryAccount, Contract } from '@aeternity/aepp-sdk';
import fs from 'fs';

const CONTRACT_ADDRESS = 'ct_2Hyt9ZxzXra5NAzhePkRsDPDWppoatVD7CtHnUoHVbuehwR8Nb';
const node = new Node('https://mainnet.aeternity.io');
const account = new MemoryAccount(process.env.AE_PRIVATE_KEY);

const aeSdk = new AeSdk({
  nodes: [{ name: 'mainnet', instance: node }],
  accounts: [account],
});

const aci = JSON.parse(fs.readFileSync('./contracts/Tipping_v3.aci.json', 'utf8'));
const contract = await Contract.initialize({
  aci,
  address: CONTRACT_ADDRESS,
  onAccount: aeSdk,
  onNode: aeSdk.api,
});

const result = await contract.post_without_tip('Hello from the SDK', []);
console.log(result.decodedResult.toString(), result.hash);
```

The ACI ships with the agent skill at `contracts/Tipping_v3.aci.json`.

## Cost

The agent skill states that a post costs roughly **0.00001 AE** in gas. It is a single stateful
contract call with no payable amount, so the cost is gas only and does not scale with the
value of anything. Treat the figure as an order of magnitude, not a quote: gas price and the
size of the stored string both move it.

## What you cannot undo

State it plainly to anyone you onboard: a published post is permanent. There is no edit, no
delete, no "only visible to followers", and no mechanism by which Superhero, a community DAO,
or a moderator can remove the content from the chain. Moderation can hide a post from a
community surface — see [Moderation](/social/moderation) — but the bytes remain, readable by
anyone running a node, forever.
