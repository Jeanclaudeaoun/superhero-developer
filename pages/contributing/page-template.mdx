# Page Template

Every page on this site has the same shape. Copy it, fill it in, and your page will look and
behave like the ones around it.

## The template

````mdx
---
title: "Human Readable Title"
description: "One sentence for search results and social cards."
---

# Human Readable Title

One to three sentences of real opening prose: what this page covers, and who it is for. Lead
with the reader's problem, not with an announcement about the page.

## First real section

The actual documentation. Tables for parallel facts, code blocks for anything runnable,
plain prose for everything else.

```bash

# Every code block is runnable, or explicitly marked illustrative
node scripts/superhero-wallet.mjs balance
```
## Read more

- [Another page on this site](/aeternity/aens) — why a reader would follow it.
- [A second internal link](/contracts/aex9) — a different reason.
- [External canonical doc](https://docs.aeternity.com/) — what it adds that this page does not.

## Open questions

- Precisely what is unknown, and where someone would look to settle it.
````

## The required parts

| Part | Required? | Rule |
| --- | --- | --- |
| Frontmatter `title` | Yes | Double-quoted. Becomes the browser title and the social card title. |
| Frontmatter `description` | Yes | Double-quoted. One sentence. Becomes the meta description. |
| `# H1` | Yes | Matches the frontmatter title. |
| Opening prose | Yes | One to three sentences, before any subheading. |
| `## Read more` | **Yes** | Two to five internal links, one to four external. Every link gets a reason. |
| `## Open questions` | Only when honest | Omit it entirely if nothing is genuinely unresolved. Never pad it. |

`## Read more` is not optional and not decorative. Internal links are how this site holds
together; the reason after the dash is what makes a reader click one rather than bouncing.

`## Open questions` is the pressure valve that keeps the rest of the page trustworthy. A page
with three honest open questions is worth far more than a page with three plausible
fabrications. Phrase each as a specific question with a named place to look — "which extensions
the deployed tokens advertise; an `aex9_extensions()` call against a live sale settles it", not
"more research needed".

There are no status markers on pages. A page is either written or it is not, and the
[roadmap](/contributing/roadmap) tracks what is left.

## MDX constraints

This is Nextra 2 on the `pages/` router, compiled by `next build`. Five things break the build,
and `scripts/lint-mdx.py` catches all of them.

| Rule | Why | Do this instead |
| --- | --- | --- |
| Frontmatter values must be double-quoted | YAML reads an unquoted `: ` as a nested mapping and throws | `title: "Sophia & FATE"` |
| No bare `{` or `}` outside code | MDX parses braces as a JavaScript expression | Wrap in backticks |
| No bare `<` before a letter, `/` or `!` | MDX parses it as JSX | Wrap in backticks, or use a fenced block |
| No pipe inside inline code inside a table row | It splits the cell and mangles the table | Use a fenced code block, or describe the alternation in prose |
| No `import` or `export` statements | Pages are plain MDX by convention | See below |

**No imports means no Nextra components.** Callouts, tabs and steps all require an import from
`nextra/components`, so this site does not use them. A blockquote, a table and a fenced code
block cover everything those components do. Math is a fenced ```text block — LaTeX is not
enabled.

## Code block conventions

- **Tag the language.** `bash`, `js`, `json`, `text`, `mdx`. Nextra 2 is configured with
  `defaultShowCopyCode: true`, so every block gets a copy button — an untagged block still
  copies, but loses highlighting.
- **Make it runnable, or say it is not.** Real commands with real paths. If a block is
  illustrative — an excerpt, a signature, pseudocode — say so in the line above it or in a
  comment on the first line.
- **Show output only when it is the point.** For a CLI command whose JSON shape a reader needs,
  show it. For `pnpm build`, do not.
- **Placeholders in angle brackets go inside a fenced block**, never inline in prose, because a
  bare `<` breaks the build.

## Cross-linking

Internal links are root-relative with no file extension: `/aeternity/aens` — never a filename
like `aens.mdx`, and never an absolute URL back into this site. The linter resolves every one
against the real page tree and fails on a broken target, so a typo cannot ship.

Link to the live product where the reader can actually do the thing. Those URLs come from
`superhero/src/routes.tsx` — for example `https://superhero.com/trends/create`,
`https://superhero.com/voting`, `https://superhero.com/defi/swap`,
`https://superhero.com/faq`, `https://superhero.com/whitepaper`.

## Navigation

Each directory has a `_meta.json` mapping page slug to sidebar label, in sidebar order. Adding a
page means adding it there in the same change — the linter fails on a page missing from its
`_meta.json`, and on a `_meta.json` entry with no page.

```json
{
  "index": "Overview",
  "why-aeternity": "Why æternity",
  "accounts-and-keys": "Accounts & Keys"
}
```

The root `pages/_meta.json` also defines the section separators and the external nav links.
Changing section structure is a deliberate act — coordinate it rather than doing it in passing.
