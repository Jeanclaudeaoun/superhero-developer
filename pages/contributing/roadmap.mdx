# Documentation Roadmap

Nearly every page on this site is written. What remains is **verification** — the facts that
could not be confirmed while the pages were being drafted, which each page declares honestly
under its own `## Open questions` heading.

This roadmap is built from those declarations rather than from a guess at what might be missing.
At the time of writing: **157 pages, 134 of them carrying open questions, 370 questions in
total.** Regenerate the raw list at any time:

```bash
# Pages with unresolved questions
grep -rl "## Open questions" pages/

# Pages still carrying outline scaffolding, i.e. not yet written
grep -rln '^> \*\*Page brief\*\*' pages/

# Every open question, one per line, prefixed by its page
python3 - <<'EOF'
import os, re
for root, _, files in os.walk('pages'):
    for f in sorted(files):
        if not f.endswith('.mdx'):
            continue
        p = os.path.join(root, f)
        m = re.search(r'^## Open questions\s*$(.*?)(?=^## |\Z)', open(p).read(), re.M | re.S)
        if not m:
            continue
        for item in re.split(r'\n(?=[-*] )', m.group(1).strip()):
            print(p, '::', ' '.join(item.split()))
EOF
```

The questions cluster into five kinds of work. They are ordered by leverage: the first item
closes more questions per hour than everything below it combined.

## Priority 1 — One session with network access

Roughly **56 open questions** exist purely because outbound network access was blocked while the
pages were written. No research is needed to close them, only a machine that can reach a node
and `api.superhero.com`. This is by far the highest-value pass available.

becomes unverifiable again the moment the chain state moves.

## Priority 2 — Get the Sophia sources

**27 open questions across 25 pages** say some version of "settle it from the `.aes` source".
The repositories vendor **ACIs**, which give signatures, `stateful` and `payable` flags — but not
bodies. Every question about *what a contract actually checks* is therefore unanswerable from
what is here.

| Contract source wanted | What it would settle |
| --- | --- |
| `DAO.aes` | Whether `vote` can top up an existing stake; whether `revoke_vote` and `withdraw` are height-gated on chain or only in clients; whether `record_sale_transaction` is permissioned; whether a `ChangeDAO` migration transfers `CommunityManagement` ownership; whether `add_vote` validates a payout against the treasury balance — [DAO](/contracts/dao), [Voting](/dao/voting), [Treasury](/dao/treasury), [Proposals](/dao/proposals), [Replaceable DAO](/dao/replaceable-dao) |
| `AffiliationBondingCurveTokenSale.aes` | Whether `price(count)` already includes the affiliation fee, and how the unaffiliated share is burned — [Token sale](/contracts/token-sale), [Value flow](/concepts/value-flow) |
| `AffiliationTreasury.aes` | What a payout period is measured in and what advances it; whether a revoked invite returns its redemption-fee cover — [Affiliation](/rewards/affiliation), [Claiming](/rewards/claiming), [Invite links](/rewards/invite-links) |
| `CommunityFactory.aes` | What `is_private` actually restricts; the default `minimum_token_threshold` — [Moderators](/dao/moderators), [Moderation](/social/moderation), [Collections & naming](/tokens/collections-and-naming) |
| `DAOVote.aes` | The exact quorum and supermajority comparisons behind the whitepaper's 10% and 55% — [Contract security](/contracts/security), [Quorum & thresholds](/dao/quorum-and-thresholds) |
| `Tipping.aes` | Whether the deployed contract adds replay protection the whitepaper omits — [Delegated posting](/social/delegated-posting), [Tipping contract](/contracts/tipping) |
| `ProfileRegistry.aes` | Everything on [ProfileRegistry](/contracts/profile-registry) — no source *and* no ACI is vendored |
| `Poll.aes` and the governance `Registry` | Whether `vote` is rejected after `close_height` on chain; whether `add_poll` is permissioned; the snapshot height used for weighting — [Governance contracts](/contracts/governance-contracts), [Create a poll](/governance/create-a-poll) |

**The single highest-value action here is vendoring `ProfileRegistry`** — its source, its ACI and
its deployed address are all missing, which blocks four pages at once:
[ProfileRegistry contract](/contracts/profile-registry),
[ProfileRegistry identity](/identity/profile-registry), [SuperheroID](/identity/superhero-id) and
[Deployed addresses](/contracts/addresses). Its apparent successor, an `AddressLink` contract,
has an ACI committed in `superhero-com/superhero-api` but its address comes from an uncommitted
deployment-time environment variable.

## Priority 4 — Screenshots

Four pages explicitly ask for them, and no image exists anywhere in the repository. Each needs a
session with the live app and an annotation pass.

- [Navigating the app](/getting-started/navigating-the-app) — one per major section
- [Your first post](/getting-started/first-post) — the composer, with each control labelled
- [Your first trade](/getting-started/first-trade) — the trade card, every field labelled
- [Superhero Wallet mobile](/wallets/superhero-wallet-mobile) — native onboarding

Establish where images live and how they are referenced before capturing the first one; the site
has no convention for this yet.

## Priority 5 — Repository hygiene

- **`pages/index.mdx`, the site's front door, is the last page still carrying outline
  scaffolding.** Confirm with the scaffolding grep above.
- **There is no CI.** `.github/` is empty, so nothing prevents a page with broken MDX from
  merging. A workflow running `python3 scripts/lint-mdx.py` and `pnpm build` on pull requests
  would close that gap, and is maybe twenty lines.
- **`README.md` still describes the retired outline convention** — page briefs, `status` markers,
  "Sources to mine" — and points readers at a workflow that no longer exists. It needs rewriting
  to match [How to Contribute](/contributing/how-to-contribute). That file is outside the
  `pages/` tree, so whoever owns the repository root should make the change.
- **No `CODEOWNERS` and no review process.** See the open question on
  [How to Contribute](/contributing/how-to-contribute).

## Keeping this page honest

This roadmap is derived data. When you close an open question, delete it from the page it lives
on — that is the source of truth — and then update the affected row here. When you open a new
one, add it to its page first.

If the two disagree, the pages win. Rebuild this list from them rather than patching it.
