# Identity

Your identity on Superhero is your æternity address plus whatever you choose to attach to it.
Those attachments live in the `AddressLink` contract as provider links, each authorised by your
own signature over a nonce-bearing message — so there is no account system to be locked out of,
and only you can remove a link.

**`ProfileRegistry.aes` is not the identity layer any more.** Linkage moved to `AddressLink`
and the registry's indexer was removed from the backend. Custom names and the display-source
preference went with it. Anything you read in the whitepaper's "Superhero Onchain ID" section
describes a design that is not running — see
[The AddressLink contract](/identity/profile-registry) for the before-and-after.

## The shape of an identity

| Layer | What it is | Where it lives |
| --- | --- | --- |
| Address | `ak_…` public key derived from your seed | The æternity chain; you hold the key |
| Preferred AENS name | A `.chain` name you own and linked | `AddressLink`, provider `prefaens`, ownership checked on chain |
| Chain name | An AENS name derived for your address | The middleware, cached and refreshed hourly |
| X handle | An X handle you consented to link | `AddressLink`, provider `x`, OAuth checked off chain |
| Nostr key | The npub your chat identity uses | `AddressLink`, provider `nostr` |
| Bio and website | Free-text links | `AddressLink`, providers `bio` and `site` |
| Fullname, avatar, legacy username | Registry-era fields with no writer left | The frozen `profile_cache` table |

A name is never the identity. Resolution always ends at an address, and the name types differ
in how much evidence backs them. Read [Names](/identity/names) before you assume a displayed
handle means anything.
