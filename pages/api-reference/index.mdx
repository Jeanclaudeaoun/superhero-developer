# API Reference

`api.superhero.com` is the read API behind everything on Superhero: tokens and their prices,
posts and topics, accounts and portfolios, the DEX, trending and analytics. Reads need no
credential — a bare `curl` gets the same bytes the web app gets. Writes are authorised by wallet
signature, not by an API key.

```bash
curl -s "https://api.superhero.com/api/tokens?order_by=trending_score&order_direction=DESC&limit=5"
```

Start with [Conventions](/api-reference/conventions) — pagination, units, errors and the write flow are
shared by everything below and are not repeated per endpoint.

## Base URLs

| Network | Base URL | Chain id |
| --- | --- | --- |
| Mainnet | `https://api.superhero.com` | `ae_mainnet` |
| Testnet | `https://testnet.api.dev.tokensale.org` | `ae_uat` |

Both hosts serve identical paths. Every path in this reference begins with `/api/`.

## The four things to know before you start

1. **`limit` is capped at 100** on list endpoints — a 400 on most of them, a silent clamp on the
   DEX paths. Page rather than asking for more.
2. **Units are mixed within the same object, and the same field name means different scales on
   different endpoints.** `TokenDto.market_cap` is in aettos; the `market_cap` on a transaction
   or an OHLC candle is in AE. [Conventions](/api-reference/conventions#units) has the full table
   and the rule that predicts it.
3. **Date parameters are spelled three different ways** depending on the endpoint —
   `start_date`, `startDate` and `from_date`. Getting it wrong returns unfiltered data rather
   than an error, because loose query parameters are not whitelisted.
4. **Most reads are unthrottled, but a handful of routes allow only 10 requests per minute per
   IP.** Which ones, and what the 429 looks like, is in
   [Conventions](/api-reference/conventions#rate-limits).

## Full endpoint index

Every path in the OpenAPI-generated client, grouped by resource. Paths marked **unused** have no
caller in the web app or the agent skill.

That marking means "no client in these repositories exercises it", not "unverified" and certainly
not "unstable". Every one of them is a real route with a real controller in `superhero-api`, and
the endpoint pages in this section now describe their responses from that controller rather than
from a caller. Treat the marking as a hint about how well-trodden a path is, not as a warning.

## Is there an OpenAPI document?

Yes — the API server generates one, but it is **not mounted in production by default**.

`superhero-api/src/main.ts` builds a `DocumentBuilder` document titled *"WORD CRAFT Scan"*,
version `1.0`, and serves it only when `NODE_ENV !== 'production'` or the operator sets
`ENABLE_SWAGGER=true`:

```text
GET /api        Swagger UI
GET /api-json   the OpenAPI 3 JSON document
```

Where it is mounted, `/api-json` is the authoritative machine-readable description of the whole
surface and is what `openapi-typescript-codegen` consumed to produce the web app's client. Where
it is not, both paths 404 — deliberately, so the endpoint surface and parameter schemas are not
free reconnaissance on a public deployment. The same reasoning disables GraphQL introspection and
GraphiQL in production.

If you need a generated client for `api.superhero.com` and `/api-json` is closed there, ask the
operators to enable it or generate against a non-production deployment.

## Where this comes from

This section is written from four sources, in decreasing order of authority:

| Source | What it gives |
| --- | --- |
| `superhero-api/src/` | **The API server itself.** Controllers give routes, parameters and validation; entities give the columns actually returned; services give the formulas. Where a DTO and an entity disagree, the entity is what you receive |
| `src/api/generated/` | The web app's OpenAPI-generated client. Precise where it is current, but it lags the server in places — those are called out on the pages |
| `src/api/backend.ts` | The hand-written client — request bodies for the write endpoints, and the error-handling behaviour |
| `src/config.ts` and `superhero-agent-skill/scripts/*.mjs` | Base URLs, contract addresses, and real query construction from outside the browser |

The server is quoted in preference to the client throughout, with the file named so you can
re-check. Where the server is genuinely silent, the question is listed under `Open questions` on
the page rather than guessed.

## Open questions

- **Is Swagger enabled on `api.superhero.com` itself?** The code says it is mounted at `/api` and
  `/api-json` outside production, or in production when `ENABLE_SWAGGER=true`. Which of those the
  live mainnet deployment is running is an operator setting, not a source fact. A request to
  `https://api.superhero.com/api-json` settles it in one call.
- **Is there a published support or deprecation window?** Retired parameters are annotated and
  silently stop having an effect (see
  [Conventions](/api-reference/conventions#versioning-and-deprecation)), but no notice period,
  changelog location or removal schedule is recorded anywhere in the source.
